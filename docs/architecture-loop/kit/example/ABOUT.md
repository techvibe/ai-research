# Worked example

This example applies the loop to the design of the loop itself. It provides a
complete set of populated records you can inspect and adapt. It is not a paper
about a separate organization, and it contains no employer-specific context.

The main paper is `run/paper.md`. Delivered publications are under `run/output/`.
The architecture registry is `run/architecture.json`; editable Mermaid sources
and rendered SVGs are in `run/diagrams/`. The PowerPoint also contains native
editable diagram shapes and speaker notes.

The recommendation is intentionally conditional: pilot the process against a
simpler checklist. Local tests demonstrate structural behavior; they do not
establish an improvement in decision quality. See ../VALIDATION.md for results
and inspection limitations.

For your own project, create a new run from templates/brief.json rather than
relabeling this example's claims or pretending its sources support a new topic.
